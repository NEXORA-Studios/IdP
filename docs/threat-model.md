# NEXORA IdP — 威胁模型

本文件定义身份平台的主要威胁、控制措施和安全验收边界。具体部署秘密、备份和发布流程见 [`deployment.md`](./deployment.md)。

## 1. 保护目标

- 只有经过验证的用户和已登记客户端才能完成授权。
- 授权码、令牌、会话和密钥不能被窃取后长期复用。
- `(iss, sub)` 稳定且不会被邮箱变化混淆。
- 账户、授权、客户端和管理员操作可追踪。
- 禁用账户、密码变更和授权撤销能按策略生效。
- 日志、备份和错误响应不泄露认证秘密。

## 2. 信任边界

公网用户、第一方客户端、反向代理、Accounts Portal、OIDC Provider、Identity Core、Authorization Core、管理后台、PostgreSQL、邮件服务、密钥存储和资源服务器均是独立边界。公网只信任受配置的 HTTPS 代理头；应用不应让前端直接访问数据库或私钥。

## 3. 主要威胁与控制

| 威胁                         | 控制                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| 恶意 Redirect URI 导出授权码 | 仅允许登记 URI，严格字符串匹配；禁止开放重定向              |
| 授权码重放或跨客户端使用     | 短期、一次性、绑定客户端/URI/PKCE                           |
| PKCE 绕过                    | 所有第一方客户端强制 `S256`，校验 verifier                  |
| Token 伪造或算法降级         | 受限算法白名单、Issuer/Audience/Expiry 校验、受控私钥       |
| Access Token 长期有效        | 初始 5–10 分钟，资源服务器完整验证                          |
| Refresh Token 重放           | 轮换、重放检测、绑定授权、撤销和过期；重用已轮换令牌时撤销整条授权链       |
| 账户接管                     | Argon2id、邮箱验证、密码重置单次令牌、限流、会话轮换        |
| CSRF/XSS/开放重定向          | 安全 Cookie、CSRF、CSP、输出编码、限制 return_to            |
| 代理头伪造                   | 只信任已知反向代理，固定 Issuer，不动态拼 URL               |
| 管理权限滥用                 | 独立管理员权限、最小权限、再次认证/MFA、完整审计            |
| 数据库或备份泄露             | 最小 DB 权限、网络隔离、加密备份、秘密不入库/日志           |
| 签名私钥泄露                 | Vault（单实例，见 [`deployment.md`](./deployment.md) §3）、密钥 ID 和轮换、旧钥匙验证窗口、紧急撤销 |
| 禁用账户继续访问             | Session/Refresh 撤销、短期 Access Token、高风险资源状态检查 |
| 依赖或协议实现缺陷           | 使用成熟 Provider、锁版本、OIDC 回归和安全测试              |

## 4. 密码、账户和 Web 控制

使用 Argon2id，参数由部署环境基准测试确定；不静默截断密码。注册、登录和重置限流，响应避免枚举账户。邮箱验证和密码重置令牌必须有时效、单次使用、持久化（见 [`data-model.md`](./data-model.md) 一次性令牌）和撤销机制；密码变更或重置成功后必须撤销除当前会话外的全部已有会话并撤销 Refresh Token。

生产流量全部 HTTPS。Cookie 使用 `Secure`、`HttpOnly` 和合适的 `SameSite`，状态变更启用 CSRF。设置 CSP、HSTS、安全响应头和请求体上限，对关键端点限流。

## 5. 审计与日志

必须审计登录成功/失败、注册、邮箱验证、密码变更/重置、会话和授权撤销、客户端变更、密钥轮换、管理员操作和异常协议请求。日志不得包含明文密码、完整 Access/Refresh/ID Token、授权码、Cookie、Client Secret、私钥、重置令牌或可直接认证的秘密。

## 6. 安全测试

至少测试：替换 Redirect URI、已用授权码重放、错误 PKCE verifier、跨客户端授权码、过期 Reset Token、越权读取他人资料、禁用账户登录、错误 Audience、恶意 `return_to`、不可信代理头、公开客户端秘密暴露、日志敏感数据泄露，以及 Refresh Token 轮换后重用（必须失败并撤销整条授权链）。

发布前必须通过关键协议测试，修复或批准处置所有严重/高危问题，完成密钥分离、备份恢复、TLS、审计、监控、告警和回滚验证。

## 7. 残余风险

纯本地 JWT 验证无法即时感知账户禁用；令牌有效期内仍存在访问窗口。通过短期令牌、Refresh Token 撤销、服务端 Session 和高风险资源在线状态检查降低风险。多区域高可用、MFA、外部身份联合和风险评分属于后续专项设计，不应在首期隐式加入。
